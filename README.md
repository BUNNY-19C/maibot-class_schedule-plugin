# 课程表提醒（MaiBot 插件）

导入教务系统导出的 `.ics` 课表，在**上课前自定义分钟数**（默认 20 分钟）主动推送提醒。

- 支持 ICS 的重复规则（`RRULE`）、调休（`EXDATE`）、调课（`RECURRENCE-ID`）；
- 五种导入方式：**`/课程解析` 引导发文件**、直接发 ics 文件、本地文件、网址导入、手动放置后 `/课表重载`；
- **自然语言问课**：直接问「明天有课吗」，麦麦按课表用它的人设回答；
- **每个会话可以有自己的提前量**：群 A 提前 30 分钟、群 B 提前 10 分钟互不影响；
- **私聊与群聊都能作为提醒对象**，在目标会话里发一句 `/课表订阅` 即可（默认只在私聊工作，见「八、适用范围」）；
- **支持访问白/黑名单**：限制哪些群或个人能用命令、哪些能收到提醒；
- **自动识别法定节假日**：放假当天不提醒（调休上班日照常提醒）；
- 改设置不用重启：配置文件 + `/课表提前` 命令双通道；
- 重启不重复提醒、不丢提醒（漏掉的会在课开始前补发）。

---

## 一、安装

1. 把整个插件目录放进麦麦的插件目录，目录名保持 `maibot_plugin_class_schedule`：

   ```
   MaiBot/plugins/maibot_plugin_class_schedule/
   ├── _manifest.json
   ├── plugin.py
   └── ...
   ```

2. 重启麦麦。首次启动时 Runner 会：
   - 按 `_manifest.json` 自动安装依赖 `python-dateutil`；
   - 生成 `config.toml`；
   - 在插件数据目录下创建 `ics/` 子目录。

> 📝 `_manifest.json` 里的 `author.url` 与 `urls.repository` 必须是非空的
> http/https 地址（麦麦的清单校验会拒绝空值），目前指向本仓库。
> 若你 fork 后自用，记得改成自己的地址。

3. 在 WebUI 的插件配置里确认「提前分钟数」（默认 20）符合需要。

## 二、导入课表的五种方式

### 方式 1：命令引导导入（推荐）

在聊天里发：

```
/课程解析
```

麦麦会请你把 `.ics` 文件发过来，然后你直接把文件发到聊天里即可 —— 插件自动识别、
解析、导入，并由麦麦用它自己的语气回你结果（见「六、回复风格」）。

进入等待状态的这段时间（默认 10 分钟，可调 `file_import.arm_minutes`）有额外好处：
**发错文件会被明确指出来**。比如你发了个 zip 或截图，麦麦会告诉你"这不是课表文件"；
而平时（没发命令时）收到无关文件它会保持安静，不打扰正常聊天。

### 方式 1b：不发命令，直接发文件

也可以跳过命令，**直接把 `.ics` 丢给机器人**——插件一样会识别并导入。
适合你已经很熟这套流程、不需要引导的场景。

两种方式共同的行为：

- **同名文件重发 = 更新**，不会堆积旧课表（调课后的旧时间不会再提醒）；
- 同一份文件重复发会被认出来，不会重复导入；
- 群聊、私聊都支持，但受适用范围（默认只走私聊）与访问名单约束；
- 导入完成后，在需要收提醒的会话里发一次 `/课表订阅`。

> 适配器把文件放在**本地/内网地址**时默认会被安全策略拒绝（防止有人拿文件消息当
> 跳板探测内网）。插件日志会明确提示被拒的地址；确认那是你自己适配器的文件服务后，
> 把该主机填进 `file_import.allowed_hosts`（如 `127.0.0.1:3000`）即可放行。

### 方式 2：本地文件（内网教务只能用这个）

把 `.ics` 文件直接放进课表目录：

```
data/plugins/local.class-schedule/ics/我的课表.ics
```

放进去后最多等 `scan_interval_seconds`（默认 300 秒）自动识别，
或者在聊天里发 `/课表重载` 立即生效（需在当前适用范围内，默认私聊）。

> 教务系统一般在「我的课表 → 导出 / 下载」里提供 **iCalendar / .ics / 日历导出** 选项，
> 也可能给一个 `webcal://` 订阅链接。拿到文件后直接丢进上面的目录即可。

### 方式 3：网址导入

```
/课表导入 https://example.com/my-calendar.ics
```

下载后的文件会保存进同一个 `ics/` 目录，之后和本地文件一样被扫描。

**同一网址重复导入 = 更新那份课表**（会覆盖上一次的下载结果），
所以课表变动后重新导入一次即可，不会残留旧课程。

> ⚠️ **只允许公网 http/https 地址。**
> 出于 SSRF 防护，回环、私有、链路本地、保留地址（含 `127.0.0.1`、`192.168.x.x`、
> `169.254.169.254`、`100.64.x.x` 等）以及每一跳重定向都会被拒绝。
> 校园**内网**的教务地址请改用方式 1。

### 方式 4：手动放好后重载

```
/课表重载
```

## 三、设置提醒对象

在**私聊**里发（默认只在私聊工作，见第八节）：

```
/课表订阅
```

- **私聊**：只有你和机器人的那个私聊窗口收到提醒；
- **群聊**：整个群都会收到提醒——但需要先把 `access.chat_scope` 改成
  `"both"`，默认是只走私聊的。

可以同时订阅多个私聊会话，各自独立收到提醒。取消订阅：

```
/课表退订
```

> 也可以在配置文件里填 `target_streams` 固定推送若干会话，但推荐用
> `/课表订阅` —— 不用去找会话 ID，且支持随时增删。
> 想让配置里的会话也有独立提前量，在那个会话里发一次 `/课表提前 N` 即可。

### 在配置里填目标：QQ 号还是会话 ID？

两种都能用，插件会自己分辨：

| 你填的 | 插件怎么理解 |
| --- | --- |
| `123456789`（纯数字） | **用户号**，自动解析成对方的私聊会话（也可写 `qq:123456789`） |
| `0123456789abcdef0123456789abcdef` | **会话 ID**，原样使用 |

纯数字能当用户号用，是因为 MaiBot 的会话 ID 是 32 位十六进制、不可能是纯数字。
解析需要对方**先给机器人发过消息**（否则机器人不知道那个会话），解析不到时日志
会明确告诉你，`/课表状态` 里也能看到。

> 为什么不能直接把 QQ 号当会话 ID 用：MaiBot 里 `stream_id` 和用户号是两回事。
> 实测：同一个人，私聊会话 ID 是一串 32 位十六进制，QQ 号则是一串纯数字——
> 把 QQ 号当 `stream_id` 填进去会**静默发不出去**（日志里没有任何报错）。
> 所以插件现在两种写法都认。

## 四、自定义提前多久提醒（按会话）

提前量分两层：**配置里的默认值** + **每个会话的单独设置**，后者优先。

| 方式 | 操作 | 生效范围 |
| --- | --- | --- |
| 会话设置 | 在当前会话发 `/课表提前 30` | **仅当前会话**，其他会话不受影响 |
| 会话恢复 | 发 `/课表提前 重置` | 当前会话回到配置默认值 |
| 配置默认 | `reminder.remind_before_minutes` | 所有未单独设置的会话 |

`/课表提前`（不带参数）查看本会话当前生效值与配置默认值。

举例：在群 A 发 `/课表提前 30`、在群 B 发 `/课表提前 10`，那么同一节课
群 A 会在 30 分钟前收到提醒，群 B 在 10 分钟前收到，互不干扰。
在没订阅过的会话里直接发 `/课表提前 30`，会**顺手把该会话订阅上**
（既然要在这里设提前量，显然是想在这里收提醒）。

设为 `0` 表示**上课的时刻**提醒（此时「补发宽限」会自动放宽到至少一个检查
周期，否则 60 秒的窗口可能被检查间隔整个跨过去，导致漏提醒）。

> 退订会把该会话的提前量一并清掉，不会留下无法清理的孤儿设置。

## 五、命令一览

| 命令 | 说明 |
| --- | --- |
| `/课表` | 查看今天的课 |
| `/课表明日` | 查看明天的课 |
| `/课表本周` | 查看今天起七天的课 |
| `/课表导入 <网址>` | 从公网 http/https 网址导入 ics |
| `/课程解析` | 引导导入：回你一句提示，然后等你发 ics 文件（也可写 `/课表解析`） |
| `/课表重载` | 重新扫描课表目录 |
| （把 .ics 文件发给机器人） | 直接导入课表，回执由 replyer 来说 |
| `/课表订阅` | 把当前会话设为提醒对象（默认仅在私聊可用） |
| `/课表退订` | 取消当前会话的提醒（并清掉它的提前量） |
| `/课表提前 [分钟]` | 查看/设置**本会话**的提前量，`重置` 回到配置默认 |
| `/课表假日` | 查看节假日数据状态、今日性质与最近假日 |
| `/课表状态` | 查看运行状态、本会话可用标识、提醒会话列表（含各会话提前量）与名单模式 |

另外注册了一个 LLM 工具 `query_class_schedule`，所以直接问「今天有什么课」
「下节课是什么」麦麦也能答上来。

> ⚠️ 这个工具**不受访问名单限制**，原因是麦麦调用工具时只把模型给的参数传下来，
> 没有任何会话信息（已在本机麦麦 1.2.0 上实测确认）。如果机器人也在你不放心的
> 群里，请把 `access.tool_query_enabled` 关掉，详见第六节。

## 六、自然语言问课

直接问就行，不用记命令：

> 你：明天有课吗
> 麦麦：明天上午 9:55 机械设计，B207，张美华的课喵。下午没课。

做法是把课表**注入到麦麦的规划器上下文**里（命名 Hook
`maisaka.planner.before_request`），它答题时课表就在眼前。比起只给一个 LLM 工具，
这样更可靠——工具要模型自己决定调用，实测它经常想不起来调。

**默认只在聊到课表相关话题时注入**（`mode = "on_topic"`）。因为那个 Hook 每条消息
都会触发，无脑注入等于每条消息都多几百 token，还可能让模型跑题。触发词是
「课表 / 上课 / 下课 / 教室 / 第几节 / 有课 / 考试 / 放假…」这类**课表专有词**，
刻意不含「今天 / 明天 / 几点」这种通用词——它们几乎每条消息都有。

```toml
[nl_query]
enabled = true            # 开启自然语言问课
mode = "on_topic"         # on_topic 只在相关话题注入；always 每条都注入
days = 3                  # 注入未来几天的课
max_lines = 12            # 最多几条，控制 token
extra_keywords = []       # 额外触发词，如 ["大物", "工训"]
```

注入的内容长这样（带放假标注，并明确告诉模型别编造）：

```
【课表】当前 2026-09-15 14:30 周二，未来 3 天的课：
- 09-15 今天 16:35-20:15 工程创新训练 @实训楼1号楼底楼7号门大厅
- 09-16 明天 09:55-11:15 机械设计 @B207 张美华
- 09-17 周四（中秋节放假）
（以上是真实课表数据，回答与上课相关的问题时按此作答；没列出的时间段就是没课，不要编造）
```

想让它更主动（不用你问就提），把 `mode` 改成 `always`；代价是每条消息多一些 token。

另外仍保留 `query_class_schedule` 工具作为补充路径（显式查询时用）。

## 七、回复风格：让麦麦自己说话

插件的文案**不带任何固定口吻**：它只把事实（课程名、时间、地点、提前量）准备好，
说法由麦麦按**宿主的人设**决定。人设从宿主全局配置读（`bot.nickname`、
`personality.personality`、`personality.reply_style`），所以装在谁的 bot 上就是谁的声音。

```toml
[reply]
style = "persona"                 # 提醒的发送方式，见下表
ack_style = "persona"             # 提示语/回执的发送方式
fallback_after_seconds = 90       # 仅 proactive 模式：多久没确认发言就兜底
persona_hint = ""                 # 额外要求，如"一句话说完，别加表情"
fallback_to_fixed = true          # replyer 明确拒绝时退回直发
persona_timeout_seconds = 12      # persona 模式生成文案的超时，超时改用模板
```

### 三种发送方式

| 方式 | 机制 | 风格 | 送达 |
| --- | --- | --- | --- |
| `persona`（默认） | 让模型按宿主人设生成一句话，再由插件 `send.text` 发出 | 有宿主风格 | **必定送达** |
| `fixed` | 插件模板原文直发，不经过模型 | 机器口吻 | 必定送达 |
| `proactive` | 交给主链路的 replyer 开口（最像"本人自己在说"） | 最自然 | 会延迟，靠验证兜底 |

`persona` 是默认值：它兼顾了风格与送达——文案是模型写的，但发送不依赖主链路，
所以不会出现"模型想好了却没说"的情况。模型不可用时自动退回固定模板。

两处与省事/稳妥有关的实现细节：

- **一节课只请求模型一次**。同一节课发给 N 个会话时，文案是同一段（事实完全相同），
  生成一次后复用。逐会话生成会让检查循环串行等 N 次模型，N 个群就是 N 倍延迟。
- **生成有超时**（`persona_timeout_seconds`，默认 12 秒）。提醒循环是同步等文案的，
  模型卡住会拖慢整轮检查；提前量设得小（比如 0～3 分钟）时，这足以跨过某节课的
  提醒窗口。超时后该条提醒立刻改用模板文案发出，风格丢一次，但提醒不会丢。

### 为什么 `proactive` 需要兜底

实测（麦麦 1.2.0 + SnowLuma）：交给 replyer 的任务会被 Planner 接住、也能规划出
回复内容，但**可能不真的发出来，而且没有任何报错**。曾连续三次触发都是这个结果。

所以选择 `proactive` 时插件会做**发言验证**：入队后等 `fallback_after_seconds`，
通过 `message.get_recent` 检查 bot 自己有没有发言；没有就兜底直发，确保提醒不丢。

```
交付 replyer ──► 等待 N 秒 ──► 查最近消息里 bot 是否发过言
                                 ├─ 发过 ──► 完成（不重复发）
                                 └─ 没发 ──► 兜底直发
```

有个刻意的取舍：**拿不到 bot 账号时信任主链路**（不兜底）。宁可偶发漏兜底，
也不要因为查询失败就重复发一条。

## 八、适用范围（默认只走私聊）

插件的默认工作范围是**只在私聊**：课表是个人日程，提醒发到群里等于公开。

在配置的 `[access]` 节里设置：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `chat_scope` | `private` | `private` 只在私聊、`group` 只在群聊、`both` 两者都行 |

```toml
[access]
chat_scope = "private"   # 默认值；想让群聊也能用就改成 "both"
```

`chat_scope = "private"` 时，群聊里的这些都会**不响应**：

- 命令（`/课表订阅`、`/课表本周`……）——会回一句说明，不执行；
- 聊天里发来的 `.ics` 文件——不导入、也不回执；
- 自然语言问课——不把课表注入上下文（这条最关键：注入等于把课表贴进那个群的
  模型上下文里）；
- 已登记的群聊订阅——不再投递，并在日志与 `/课表状态` 里标出"按适用范围跳过"。

两条与"认不出会话类型"有关的取舍，方向是相反的，各自都有理由：

- **入站**（命令、文件、注入）认不出类型就**拒绝**：宁可少答一次，也不要把个人
  课表带进一个来源不明的会话。
- **出站**（提醒投递）认不出类型仍**照发**：你已经把某个会话登记成提醒对象了，
  因为认不出类型就静默停掉提醒，是本插件最坏的失败方式——漏提醒没有任何人
  会发现。所以配置里钉死的**裸会话 ID**（形如 32 位十六进制、没有平台与用户号）
  会照常收到提醒；想严格只走私聊，就别钉裸 ID，用 QQ 号或直接在私聊里
  `/课表订阅`（QQ 号会被解析成私聊会话，是能判定的）。

> ⚠️ `chat_scope` 管不到 LLM 工具（工具调用不带会话信息，见下），所以**群里的
> 模型仍可能通过工具问出课表**。要彻底堵住这一条，得同时关掉
> `access.tool_query_enabled`。插件在 `chat_scope = "private"` 且工具仍开启时
> 会打一条告警。

## 九、访问白名单 / 黑名单

用来限制**哪些群或个人能使用这个插件**。课表是你个人的日程，如果机器人还
在别的群里，建议开白名单，只放行你自己的群和私聊。

在配置的 `[access]` 节里设置：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `off` | `off` 不限制、`whitelist` 只允许名单内、`blacklist` 名单内被拒绝 |
| `entries` | `[]` | 名单内容，一行一个：群号、用户号或会话 ID |
| `apply_to_commands` | `true` | 是否限制命令（含 `/课表状态`） |
| `apply_to_reminders` | `true` | 是否限制提醒投递 |
| `tool_query_enabled` | `true` | 是否允许麦麦用 LLM 工具查课表（**名单管不到它**，见下） |

名单管"是谁"，`chat_scope` 管"在什么类型的会话里"，两者独立生效：命令要同时
通过这两关。所以关掉 `apply_to_commands` 不等于放开群聊。

`entries` 支持三种写法，同一份名单里可以混用：

```toml
[access]
mode = "whitelist"
entries = [
  "123456789",        # 群号
  "987654321",        # 用户号（私聊用这个）
  "qq:112233445",     # 带平台前缀的写法，等价于裸号
  "a1b2c3d4-stream",  # 会话 ID（群号取不到时用这个）
]
```

怎么拿这些号：群号就是 QQ 群号；**会话 ID** 可以在目标会话里发 `/课表状态`
看到（列表里会标出本会话）。

行为要点：

- **白名单默认拒绝**：名单外的会话，命令不执行、也不会有提醒；连会话身份都
  识别不出来时同样拒绝（宁可少答一次，也不把课表泄漏给认不出的会话）。
- **黑名单默认放行**：只禁止点名的那些会话。已经订阅过的会话，被加进黑名单
  后会自动停止收到提醒（不必先退订）。
- 匹配是**大小写敏感的精确比较**（会话 ID 可能区分大小写，放宽会变成越权
  入口），两侧空格会被忽略。
- 开了白名单却没填内容等于谁都不许用——这是刻意的失败关闭，别误开。

> ⚠️ **名单条目只在"拿得到对应标识"时才可能命中。** 如果适配器不下发群号/
> 用户号，会话身上就只剩会话 ID，此时用群号写的条目永远匹配不上（黑名单会
> 静默失效、白名单会误拒）。插件启动时若发现这种风险会在日志里告警；
> 也可以在目标会话发 `/课表状态`，那里会直接列出本会话的全部可用标识，
> 照抄进名单即可。

### 名单管不到 LLM 工具（实测结论）

麦麦调用插件工具时，只把**模型给的参数**传下来，没有任何会话信息
（`component_query._build_tool_executor` 只传 `function_args`）。也就是说工具
根本不知道自己在哪个群被调用，名单在工具这条路上无法判定：

- 白名单下工具**不会**被拒绝——维持原样会变成"名单一开工具就废"；
- 黑名单下工具**不会**被拦截——被拉黑的群仍能问出课表。

所以真正的控制只有 `access.tool_query_enabled` 这一个开关：

```toml
[access]
tool_query_enabled = false   # 关掉 LLM 查课表能力，避免被人问出来
```

开着名单又留着工具时，插件启动会打一条告警提醒你这层缺口。

命令这条路径是**能**判定的：麦麦的命令执行器会补上 `stream_id`、`group_id`、
`user_id`，并把消息挂在 `message.message_info` 下——插件正是靠这些取身份。
这两组字段契约都固定成了测试（`tests/test_access.py::TestRealMaiBotPayload`），
上游若改动会立刻失败。

## 十、法定节假日自动识别

放假当天不该提醒你上课。插件会自动判断某一天是不是法定节假日，是就不发提醒。

**数据从哪来**：默认取 [holiday-cn](https://github.com/NateScarlet/holiday-cn)
项目按年发布的 JSON，它由国务院公告生成，包含每年的放假安排与**调休上班日**。
插件启动时按需下载（只下当年和次年），缓存到本地，默认每 12 小时检查一次
是否过期。纯配置项在 `[holiday]` 节。

**关键区别：调休上班日不算假日**

数据里 `isOffDay: false` 的条目是**周末补班**，那天是要上课的。插件只对
`isOffDay: true` 的日子跳过提醒，所以调休上班日照常提醒。

**怎么确认它在工作**

```
/课表假日
```

会显示：数据覆盖了哪些年份、今天是不是假日、最近几个假日的日期、数据来源。
`/课表状态` 里也有这几行。`/课表本周` 的日期行会标注 `🎉元旦放假`、
`🔁春节调休上班`，一眼能看出某天为什么没提醒。

**拿不到数据时会怎样**

**照常提醒，不跳过**。这是刻意的：假日数据依赖网络，而「假期里多提醒一次」
只是烦人，「上课日漏提醒」会真的误事。缺少哪一年的数据会在启动日志里告警，
`/课表假日` 也会标出来。所以断网、数据源挂掉都不会让你错过上课。

**校历自定假日**（寒暑假、校庆、调课）用 `holiday.extra_dates` 补：

```toml
[holiday]
extra_dates = [
  "2026-11-15",   # 只算 2026 年这一天
  "05-20",        # 每年 5 月 20 日（校庆）
]
```

`extra_dates` 与 `skip_off_days` **互相独立**：前者是你逐条写下的名单，始终生效；
后者只管"要不要因为法定节假日跳过"（数据源里那些）。所以关掉
`skip_off_days` 也不会让你的寒暑假失效。

**反向情况：放假表说放假，但你们要补课**，用 `holiday.exclude_dates` 翻回来
（写法相同）。这类日期优先于任何假日判定（包括 `extra_dates`），照常提醒：

```toml
[holiday]
exclude_dates = ["2026-10-01"]   # 国庆补课，那天要上课
```

这两项改完立即生效，不用重启。

**数据源换成别的**：`holiday.source_url_template` 里的 `{year}` 会替换成四位年份。
私有部署的节假日服务也支持，但**只允许公网 http/https 地址**（与导入课表同一套
SSRF 校验，内网地址会被拒绝）。

> 提醒以**纯文本**发送。麦麦主机与内置的 NapCat / SnowLuma 适配器都不支持
> markdown 之类的自定义消息段（整个代码库里没有 `qq_markdown` 的实现），
> 所以不做"看起来能开、其实每次都在降级"的开关。

默认模板：

```
⏰ {minutes_label}：{course}
🕐 {time_range}{location_part}
```

渲染结果：

```
⏰ 20 分钟后上课：高等数学
🕐 08:20-10:00
📍 教三-201
```

可用占位符：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{minutes_label}` | 自然的提前量描述 | `20 分钟后上课` / `马上上课` |
| `{minutes}` | 提前量数字 | `20` |
| `{course}` | 课程名 | `高等数学` |
| `{time_range}` | 时间段 | `08:20-10:00` |
| `{start}` / `{end}` | 开始/结束时刻 | `08:20` |
| `{location}` | 地点 | `教三-201` |
| `{location_part}` | 带图标的地点行（无地点时为空） | `\n📍 教三-201` |
| `{description}` | 备注（常见为教师名） | `教师：张三` |
| `{description_part}` | 带图标的备注行 | `\n📝 教师：张三` |
| `{date}` / `{weekday}` | 日期 / 星期 | `2026-09-01` / `星期二` |

写错的占位符会被原样保留，不会导致整条消息发不出去。

> **检查间隔与提前量的关系**：提醒窗口是「课前 N 分钟」到「课后补发宽限」。
> 如果检查间隔比这个窗口还长，某一轮检查会整段跨过去、这节课就漏了。插件会
> 自动把窗口放宽到至少覆盖一个检查周期来**保证不漏**，代价是检查间隔设得很大
> 时提醒可能迟到（启动日志里会告警）。默认的 60 秒间隔 + 20 分钟提前量不会
> 触发这种情况，保持默认即可。

## 十二、时间口径（重要）

为避免在 Windows 上依赖 `tzdata` 数据包，本插件对 ICS 时间做如下处理：

| ICS 里的写法 | 处理方式 |
| --- | --- |
| `DTSTART;VALUE=DATE:20260901` | 全天事件，**不参与上课提醒** |
| `DTSTART;TZID=Asia/Shanghai:20260901T080000` | 按本地墙上时间取用（即 08:00 就是 08:00） |
| `DTSTART:20260901T000000Z` | 视为 UTC，换算成系统本地时间 |

国内教务导出的课表时间基本都是「本校本地时间」，直接取墙上时间不会错。
如果课表用的是别的时区、且你需要跨时区提醒，请把 ICS 先转成本地时间再导入。

**重复规则**由 `python-dateutil` 展开，因此需要 `python-dateutil>=2.8.0`
（已在 `_manifest.json` 里声明，Runner 会自动安装）。

## 十三、数据文件

```
data/plugins/local.class-schedule/
├── state.json      # 提醒会话（含各自提前量）、已提醒记录
├── holidays/       # 法定节假日数据缓存（按年）
│   ├── 2026.json
│   └── 2027.json
└── ics/            # 所有课表文件
    └── *.ics
```

课表永远以 ics 文件为唯一数据源，删掉 `ics/` 里的文件就等于删掉对应课程。
`holidays/` 可以整个删掉（会自动重新下载）。`state.json` 可直接删除（会重置
订阅、各会话提前量与去重记录，不影响课表）。

`state.json` 里每个提醒会话长这样：

```json
{
  "stream_id": "会话 ID",
  "chat_type": "group",          // 或 private
  "group_id": "群号",
  "user_id": "用户号",
  "label": "群名/昵称",
  "lead_minutes": 30,            // null 表示跟随配置默认值
  "added_at": "2026-09-01T10:00:00"
}
```

> 从早期版本升级上来的旧状态文件（裸会话 ID 列表 + 一个全局提前量）会自动
> 迁移：旧会话全部保留，原全局提前量平摊给它们，之后就能各自调整。

### 实现说明：为什么用 Hook 而不是 EventHandler

麦麦 1.2.0 里**消息类核心事件没有真正派发**——`event_bus.emit(EventType.ON_MESSAGE)`
以及 `POST_SEND` / `AFTER_SEND` 那几行在源码里都是注释状态，实际只有
`ON_START` / `ON_STOP` 会发出。所以「聊天里发文件」这个功能改用**命名 Hook**
`chat.receive.after_process`（`bot.py` 里是活代码，每条入站消息都会经过），
并选 `observe` 模式 + 后台任务，避免下载文件把入站链路阻塞到适配器超时。

如果哪天麦麦把事件派发接回来了，这段可以改回 `@EventHandler`；
`tools/verify_with_maibot.py` 里有一条检查会盯着 Hook 是否仍注册在预期名字上。

### 用真实的麦麦验证

单元测试用的是替身；下面这个脚本调用**麦麦自己的代码**做集成验证：

```bash
python tools/verify_with_maibot.py                 # 自动查找麦麦安装
python tools/verify_with_maibot.py --maibot "D:\Maibot\MaiBot OneKey\resources\modules\MaiBot"
```

它会在临时目录里搭一个假项目根（不动你的麦麦安装），然后：

| 阶段 | 验证内容 |
| --- | --- |
| 1 | 麦麦真实的 `PluginLoader`：清单校验、依赖解析、包导入、组件收集 |
| 2 | 麦麦的配置归一化：生成并读回 `config.toml`，再注回插件 |
| 3 | 真实 `PluginContext`：`on_load` → `/课表订阅` → `_tick` 真的走能力协议发消息 → 热更新 → `on_unload` |
| 4 | 主机字段契约：命令载荷能取出群号/用户号；Tool 载荷确实没有会话信息 |
| 5 | 节假日语义：放假跳过、调休上班不跳过、缺数据 fail-open |

**已验证环境**：麦麦 1.2.0 + **SnowLuma 适配器**（一键包
`resources/modules/MaiBot`，适配器在 `plugins/snowluma-adapter`），59 项检查全通过。

此外还在**真实运行中的麦麦**里跑通了完整链路（SnowLuma 适配器，私聊）：
插件被文件监听器自动加载 → 生成 `config.toml` → 下载当年节假日数据 →
把配置里的 QQ 号解析成会话 → 读取课表 → 到期判定 → 通过 SDK 能力发出 → 到达 QQ。
日志证据（会话 ID 已脱敏）：

```
[扩展插件] 已启动：已加载=1（local.class-schedule），失败=0
[ClassSchedule] 配置目标「<用户号>」已解析为会话 01234567...
[ClassSchedule] 已提醒「【测试】课程表提醒」（提前 20 分钟，发送 1/1）
```
需要麦麦的依赖在线（`structlog`、`tomlkit`、`pydantic`、`packaging`、
`maibot-plugin-sdk`）。

适配器相关的事实都已核对过源码：SnowLuma 的网关是
`route_type="duplex"`（收发都支持，所以 `send.text` 能到 QQ），`platform` 是
`"qq"`，群号在 `message_info.group_info` 下且**只有群聊才有这个键**。

跑这个脚本可以提前发现"单元测试测不出"的集成问题——本插件就有两处是靠它
才暴露的：清单缺 `author.url` 被真实校验拒绝；以及**工具调用拿不到会话信息**，
导致原先的"工具也过名单"设计根本不成立。

和"插到最后一条 system item 之后"这个位置选择。

`proactive` 的发言验证与"读宿主人设生成文案"这两个思路借鉴自
[DCY501/maibot-reminder-plugin](https://github.com/DCY501/maibot-reminder-plugin)
（MIT）——它用 `message.get_recent` 判断 bot 是否真的发过言，
解决了"交给 replyer 后可能静默失败"这个坑。

## 十六、已知限制

- **网址导入是「拉一次」，不会自动定期更新**：课表变动后需要重新执行
  `/课表导入 <同一网址>`（会覆盖上一次的结果）。本地文件方式则改文件即生效。
- **导入文件与手动文件的命名空间**：网址导入的文件名形如
  `imported-<原始文件名>-<网址哈希>.ics`，因此不会覆盖你手动放进目录的文件；
  但**手动放的文件不会**被导入覆盖，需要自己管理。
- **仅识别 `.ics` 扩展名**：`.ical` 等请改名后再放入。适配器如果给了
  `mime_type = text/calendar`，那即使文件名没后缀也能认出来。
- **不接受校园内网地址**：见「方式 3」的安全说明。
- **调课覆盖**（`RECURRENCE-ID`）支持「改时间/改地点/改课程名」，
  但不支持把一次课拆成多次的复杂场景。
- **无法解析的重复规则不会静默失效**：这门课会按"只上一次"处理，并在日志里
  告警一次（否则一门每周重复的课会无声消失）。规则细到按秒/毫秒、或一个窗口内
  能展开出上千次的，同样会被拒绝或截断——那类规则基本只可能是坏数据或恶意文件，
  而展开跑在提醒循环的同步路径上。
- **全天事件**（如校历、节假日）不会触发提醒。
- **课程列表消息最多 30 行**（超出显示「仅显示前 30 行」），
  课程名与地点超长会被截断。
- **法定节假日数据依赖网络**：拿不到数据时不跳过提醒（照常提醒），并在日志与
  `/课表假日` 里标出缺哪些年份。数据由第三方项目（holiday-cn，取自国务院公告）
  提供，也可以换成你自己的数据源。
- **寒暑假、校历自定假日不在法定节假日数据里**：数据源只含国家法定节假日，
  寒暑假这类校历安排需要自己用 `holiday.extra_dates` 补。
- **调休上班日按上课日处理**：那天会照常提醒。若你们学校补班日不上课，把那天
  用 `extra_dates` 加进假日列表即可；反过来法定假日要补课的，用 `exclude_dates`。
- **节假日数据是后台下载的，不会阻塞提醒**：即使数据源很慢或超时，提醒判定
  照常进行（拿不到数据就不跳过）。下载失败会在日志里告警一次。
- **群号/用户号不一定拿得到**：接口能提供时才记录，取不到时用会话 ID 兜底
  （`/课表状态` 里能看到），名单匹配三种标识都支持。群名/昵称同理，只用于展示。
- **聊天文件走适配器给的地址下载**：若该地址在本机/内网，默认被安全策略拒绝，
  需要你在 `file_import.allowed_hosts` 里点名放行（日志会告诉你被拒的地址）。
- **`proactive` 模式的送达依赖麦麦的回复流程**：实测它可能只规划不发声且无报错，
  插件靠 `message.get_recent` 验证并在超时后兜底直发。默认的 `persona` 没有这个问题
  （文案由模型生成，发送走直发）。
- **LLM 工具不受访问名单限制**：麦麦调用工具时不传任何会话信息，名单在这条
  路上无法判定（已实测）。要防止课表被问出来，把 `access.tool_query_enabled`
  关掉。命令路径不受此影响，名单照常生效。
- **提醒会话默认上限 20 个**：可调 `target.max_subscriptions`。
- **名单匹配大小写敏感**：会话 ID 若含字母，请从 `/课表状态` 原样复制。

# 导入课表

课表永远以 **`.ics` 文件**为唯一数据源,所有导入方式最终都落到同一个目录:

```
data/plugins/github.BUNNY-19C.class-schedule/ics/
```

好处是你随时能直接看到、替换、删除文件,不需要维护「文件 + 数据库」两份状态。

## 方式 1:命令引导导入(推荐)

在聊天里发:

```
/课程解析
```

麦麦会请你把 `.ics` 文件发过来,然后你直接把文件发到聊天里即可——插件自动识别、
解析、导入,并由麦麦用它自己的语气回你结果(见 [回复风格](behavior.md#回复风格))。

进入等待状态的这段时间(默认 10 分钟,可调 `file_import.arm_minutes`)有额外好处:
**发错文件会被明确指出来**。比如你发了个 zip 或截图,麦麦会告诉你"这不是课表文件";
而平时(没发命令时)收到无关文件它会保持安静,不打扰正常聊天。

## 方式 1b:直接发文件

也可以跳过命令,**直接把 `.ics` 丢给机器人**——插件一样会识别并导入。
适合你已经很熟这套流程、不需要引导的场景。

两种方式共同的行为:

- **同名文件重发 = 更新**,不会堆积旧课表(调课后的旧时间不会再提醒);
- 同一份文件重复发会被认出来,不会重复导入;
- 群聊、私聊都支持,但受适用范围(默认只走私聊)与访问名单约束;
- 导入完成后,在需要收提醒的会话里发一次 `/课表订阅`。

文件名的识别:优先看扩展名(`.ics` / `.ical`),适配器给了
`mime_type = text/calendar` 时即使没后缀也能认出来。

### 适配器把文件放在本地/内网地址

默认会被安全策略拒绝(防止有人拿文件消息当跳板探测内网)。插件日志会明确提示
被拒的地址;确认那是你自己适配器的文件服务后,把该主机填进
`file_import.allowed_hosts`(如 `127.0.0.1:3000`)即可放行。

配置项见 [配置参考](config.md#file_import-聊天文件导入)。

## 方式 2:本地文件

把 `.ics` 文件直接放进课表目录:

```
data/plugins/github.BUNNY-19C.class-schedule/ics/我的课表.ics
```

放进去后最多等 `source.scan_interval_seconds`(默认 300 秒)自动识别,
或者在聊天里发 `/课表重载` 立即生效(需在当前适用范围内,默认私聊)。

> 教务系统一般在「我的课表 → 导出 / 下载」里提供 **iCalendar / .ics / 日历导出**
> 选项,也可能给一个 `webcal://` 订阅链接。拿到文件后直接丢进上面的目录即可。
>
> **校园内网的教务系统只能用这种方式**(内网地址不被网址导入接受,见下)。

## 方式 3:网址导入

```
/课表导入 https://example.com/my-calendar.ics
```

下载后的文件会保存进同一个 `ics/` 目录,之后和本地文件一样被扫描。

**同一网址重复导入 = 更新那份课表**(会覆盖上一次的下载结果),所以课表变动后
重新导入一次即可,不会残留旧课程。

**自动刷新**:导入时会记住来源网址(记录在 `ics/.sources.json`),之后默认每
6 小时(`source.url_refresh_hours`,可调,`0` 关闭)自动重新下载一次——
**内容有变动才覆盖文件**并通知提醒会话"课表有变动";没变化就不动作。
下载失败或远端返回坏内容时保留旧课表,下个周期再试,不影响现有提醒。

> ⚠️ **只允许公网 http/https 地址。** 出于 SSRF 防护,回环、私有、链路本地、
> 保留地址(含 `127.0.0.1`、`192.168.x.x`、`169.254.169.254`、`100.64.x.x` 等)
> 以及**每一跳重定向**都会被拒绝(自动刷新的每次下载都走同一套校验)。
> 校园内网的教务地址请改用方式 1 或方式 2。

## 方式 4:手动放好后重载

```
/课表重载
```

## 文件命名与覆盖规则

| 来源 | 落盘文件名 | 重发/重导入的语义 |
| --- | --- | --- |
| 聊天文件 | `chat-<原文件名>.ics` | 同名即覆盖(更新) |
| 网址导入 | `imported-<原文件名>-<网址哈希>.ics` | 同一网址即覆盖 |

两套前缀(`chat-` / `imported-`)**都不会覆盖你手动放进目录的文件**;反过来,
手动放的文件也不会被导入覆盖,需要你自己管理冲突。

刻意不带内容哈希:你重新导出同名课表再发一次,就应该替换掉旧的——否则调课后的
旧时间还会继续提醒。
